# anirudhgarg.dev — personal site

Static site. Vite + React + TypeScript, no UI framework, no CSS framework, no analytics.
Deploys to GitHub Pages as a **user page** from `Action-Kamen/Action-Kamen.github.io`.

---

## Run it

```bash
npm install
npm run dev          # http://localhost:5173
```

```bash
npm run build        # tsc -b && vite build  ->  dist/
npm run preview      # serve dist/ on :4173
npm run typecheck
```

Node 18 or newer. Vite is pinned to 6.x specifically so `npm run dev` works on Node 18 —
Vite 7 requires Node 20.19+ and fails hard otherwise.

> **WSL note.** This project lives on the Windows filesystem under `/mnt/c`. inotify events
> do not cross the WSL↔Windows boundary, so `vite.config.ts` turns on `usePolling`. Without
> it the dev server starts fine and then silently never hot-reloads.

## Deploy

Push to `main`. `.github/workflows/deploy.yml` builds and publishes to Pages.

One-time setup:

1. Create the repo **`Action-Kamen.github.io`** (the name must match the username exactly,
   or Pages serves it as a project page at a subpath and every absolute asset URL 404s).
2. Push this directory to it as `main`.
3. **Settings → Pages → Build and deployment → Source: GitHub Actions.** Not "Deploy from a
   branch" — the workflow uploads an artifact and that source setting ignores it.
4. Push again, or run the workflow manually from the Actions tab.

Live at `https://action-kamen.github.io/`.

### Custom domain

Add a `public/CNAME` containing just the hostname, set the DNS records GitHub documents,
then update these three places, which are the only hardcoded absolute URLs:

- `index.html` — `<link rel="canonical">`, the `og:*` tags, the JSON-LD `url`
- `public/robots.txt` — the `Sitemap:` line
- `public/sitemap.xml` — the `<loc>`

`base` in `vite.config.ts` stays `'/'` for both a user page and a custom domain. It only
changes for a **project** page, where it must be `'/<repo-name>/'`.

## Where things are

```
src/data/content.ts        Every fact on the site. Nothing is hardcoded in a component.
src/styles/tokens.css      Palette, type scale, spacing, motion. The design system.
src/styles/base.css        Reset, element defaults, layout primitives.
src/styles/app.css         Component styles.
src/styles/fonts.css       GENERATED by scripts/fonts.mjs. Do not hand-edit.
src/components/            One file per section.
src/components/figures/    The hero shader and the four project diagrams.
src/assets/gallery/        Photos. Auto-discovered at build time.
scripts/                   Font vendoring, image optimisation, the OG template.
```

### Editing content

`src/data/content.ts` is the single source of truth — experience, projects, the paper, the
achievements strip, links. Components read from it and never inline a fact. Each block
carries a `source` field naming where the fact was verified (résumé, LinkedIn export,
employment letter, Crossref), so the file can be audited without reading the components.

### Adding or changing photos

Photos live in three folders and are discovered automatically — there is no list to update.

| Folder | Used by | Shape |
|---|---|---|
| `src/assets/gallery/solo/` | the large mosaic panel | portrait, 820x1090 |
| `src/assets/gallery/group/` | the five smaller panels | landscape, 760x570 |
| `src/assets/hero/` | the hero illustration (one file) | any; SVG passes through untouched |

Drop files in, then:

```bash
npm run images        # crops, resizes, converts to WebP, deletes the originals
```

Filenames are shown in order, so prefix them (`04-lake-brienz.jpg`). The filename also
becomes the alt text unless there is an entry for it in the `ALT` map at the top of
`src/components/Mosaic.tsx` — add one there, it takes ten seconds and it is the difference
between "lake brienz" and a real description.

**From a phone, with no laptop:** GitHub → the folder → *Add file* → *Upload files* →
commit. The site rebuilds itself in about 90 seconds. The one cost is that `npm run images`
will not have run, so the original ships unoptimised. Run it next time you are at a machine;
it is idempotent and will simply fix whatever it finds.

### Changing the CV

The CV exists in **three** files: the downloadable PDF, plus one rendered image per page for
the in-page viewer. Replacing only the PDF leaves the viewer showing the old CV, so the page
and the download would disagree.

```bash
cp /path/to/new.pdf public/doc/Anirudh-Garg-CV.pdf
npm run cv            # re-renders every page, and deletes images from a longer old version
```

Needs `python3` with `pymupdf`. This is the one job that genuinely wants a laptop.

### Fonts

```bash
npm run fonts        # re-vendors, instances and subsets from Google Fonts
```

Needs `python3` with `fonttools` and `brotli`. Only rerun when a family, axis range or
glyph requirement changes — the output is committed.

### The social card

`public/og.png` is a screenshot of `scripts/og-template.html`, so it uses the site's real
typography rather than an approximation. To regenerate: copy the template into `public/`,
`npm run build && npm run preview`, screenshot `/og-template.html` at 1200×630, save to
`public/og.png`, and remove the template from `public/` again.

## Decisions worth knowing about

**No Tailwind.** The design is a token system with a hue that shifts down the page and four
hand-drawn canvas diagrams. Tailwind would have contributed a config file and a lot of class
soup without replacing any of it.

**Fonts are vendored, instanced and subset — 332 KB → 107 KB.** Three passes in
`scripts/fonts.mjs`: self-host to kill the third-party round trip, pin unused variable axes
(Newsreader's `opsz` alone was 68 KB of `gvar` deltas), then drop unreachable glyphs and
unused OpenType features. Because `opsz` is pinned at 48, Newsreader is display-only and
Instrument Sans carries body prose — a better type system than one serif at a compromise
optical size.

**One shader, and only one.** The hero evaluates real thin-film interference — the physics
that makes iridium iridescent, which is where the palette comes from — in a hand-written
WebGL2 fragment program. There is no geometry: one triangle, one fragment shader. The four
project diagrams are canvas 2D, because for tens of nodes and edges canvas is the correct
tool and WebGL would be a costume. Three.js is not a dependency; it would have been ~150 KB
gzipped to draw a single quad.

**Never call `WEBGL_lose_context.loseContext()` in a cleanup that shares a canvas.**
`getContext` is idempotent per element: once force-lost, a later `getContext('webgl2')`
returns the same dead context. It is non-null, so every guard passes and then every
`compileShader` fails with a *null* info log. React StrictMode's mount/unmount/remount
triggers this in development. Cost an hour; see the comment in `IridescenceField.tsx`.

**The accent is a CSS custom property registered with `@property`.** That is what makes
`--iri-h` animatable, so the hue can transition between sections instead of cutting. The
palette is defined twice — hex for everyone, then oklch inside an `@supports` guard —
because holding lightness constant across a hue sweep only works in a perceptual space.

**Everything heavy is lazy and pauses offscreen.** The hero shader and the figures are
separate chunks (`field`, `figures`) so a visitor who never opens a project entry never
downloads the diagram code. Every animation stops when its element leaves the viewport, and
`prefers-reduced-motion` collapses the duration tokens to 1 ms and renders each figure as a
single representative frame.

## Accessibility

Semantic landmarks, a skip link, real `<button>`s with `aria-expanded` for the project
entries, `aria-current` on the active nav item, `role="img"` plus a descriptive `aria-label`
on every canvas diagram, visible focus rings, and `prefers-reduced-motion` honoured
throughout. Verified at 375px with zero horizontal overflow.
